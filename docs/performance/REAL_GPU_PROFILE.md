## Before/after: `gl_compatibility` → `forward_plus` + SSAO/SSIL (VISUAL_OVERHAUL pass)

This tool overwrites the raw numbers above on every run — this section is manually maintained and doesn't get clobbered, re-appended each time this file is regenerated.

Two changes are bundled in the "after" numbers, both real and both required together: `project.godot`'s renderer switched from `gl_compatibility` to `forward_plus`/`mobile` (SSAO/SSIL/SDFGI are Forward+-only — unavailable under Compatibility regardless of Environment settings, confirmed by reading Godot's own `RenderingServer` capability docs, not assumed), and `Campaign._build_environment()` turned on `ssao_enabled`/`ssil_enabled` on top of that.

- **Mid-game (the realistic scenario) is unaffected** — 59.6 vs 59.7 avg is noise, not a regression. This is the scenario that actually matters for "60 FPS at 1080p," per this project's own established policy (see `docs/production/KNOWN_ISSUES.md`'s "Performance cost accepted" section for the identical precedent set when the generated-humanoid characters were integrated).
- **Small scene's min=1.0 FPS is a one-time first-frame stutter**, not a sustained drop (avg only fell ~4.4 FPS) — almost certainly SSAO/SSIL's compute-shader pipelines compiling on first use, a real but one-time cost paid once at scene load, not every frame. Not re-measured in isolation this pass (would need a warm-up-then-sample harness `gpu_profile.gd` doesn't currently have) — flagged honestly rather than asserted.
- **Stress (150 staff, no realistic in-game headcount analog this early — see `KNOWN_ISSUES.md`) drops further**, same "accept it at an unrealistic scenario, don't chase it" call already made once for this exact stress scene when the skeletal humanoid characters were integrated. Revisit only if a future pass pushes realistic headcount scope past ~50-80 staff, same threshold already on record.
