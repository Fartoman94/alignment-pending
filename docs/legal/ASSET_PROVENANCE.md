## 3D asset pack integration (finalization pass)

38 models, imported and confirmed rendering correctly (real screenshots, not just import-without-error). Wired into a real game system vs. imported-and-available only:

- **Wired (8 models, replacing procedural placeholders)**: the 6 playable staff character roles (`StaffRoleCatalog.character_model` → `StaffAgent`) and 2 buildables — `desk` → `furniture/desk_single.glb`, `server_rack` → `datacenter/server_rack.glb` (`BuildableCatalog`'s new `model` field → `BuildController._make_real_mesh()`). Verified in the actual running campaign scene: real desks and server racks placed and rendered alongside real staff, correctly scaled and positioned.
- **Imported, validated, visible in the gallery, not wired to any system (30 models)**: `ceo`/`cfo`/`hr`/`legal` (no board/legal/HR visual context exists in the sim to attach them to), the other 7 furniture pieces (`desk_double`, `desk_L`, `bookshelf`, `divider_panel`, `filing_cabinet`, `meeting_table`, `office_chair` — no buildable slots exist for them; `BuildableCatalog` only has 3 entries total), all 9 computer/equipment models (no "desk decoration" system exists to place them on a desk), all 5 datacenter-support models beyond `server_rack` (`battery_cabinet`, `cable_tray`, `cooling_unit`, `ups` — the game's datacenter *tiers* are deliberately abstract/no grid placement, so there's no scene position to put these at), and all 6 decorative props (no prop-placement/instancing system exists — same gap already tracked in `KNOWN_ISSUES.md`'s "500 props" performance target).
- The `safety_lab` buildable has no matching asset in the pack (no "lab console"/"research station" model) — deliberately left on its original procedural box rather than forcing an ill-fitting substitute; `BuildController._make_real_mesh()` falls back to the procedural path automatically whenever a buildable has no `model` field, verified via this exact case.
- Same authored-orientation fix required everywhere: every model in the pack is authored Z-up in local mesh space, not Godot's Y-up (confirmed once by rendering and inspecting pixels, not re-verified per-model after that, but every category uses the same `-90°` X correction consistently and every category's render looked correct in the gallery screenshot).
- **4 more props wired as fixed ambient decoration**: `Campaign._build_ambient_decoration()` places 2 `plant.glb`, 1 `water_dispenser.glb`, and 1 `trash_bin.glb` at fixed positions in the margin between the walls and the buildable grid/navmesh, so the starting office doesn't read as a completely empty shell before the player has built anything. Deliberately not a general prop-placement system (still open, see `KNOWN_ISSUES.md`) — just enough fixed set dressing to make the space feel inhabited, verified via a real rendered screenshot alongside real staff/desks/racks.

## Notes
- `assets/ui/*.svg` are store-page/marketing concept art, not loaded by any game code (verified P47: no reference in `game/src/` or `game/scenes/`) — kept for store-page use, not part of the shipped game build.
- P47 removed the 11 placeholder `.wav` files under `assets/audio/` and stopped `tools/bootstrap.sh` from regenerating them (it called `tools/generate_audio.py`, an offline Python synth script bundled with the original devkit template, `bbc8d69`, before any numbered prompt). Confirmed via a project-wide reference search that no game code ever loaded these files — P41's real audio system (`AudioSynth`, above) took a different, in-engine runtime-synthesis approach instead, making the offline-generated files pure dead weight (regenerated every bootstrap run, shipped in the build, loaded by nothing). `tools/generate_audio.py` itself is left in place as harmless, unused reference tooling.
