# Landing page contract audit

The landing page published this session (https://claude.ai/artifact/3JZsWSnScEDuoTKyDB6zC4) is now treated as a functional/visual contract, per explicit direction: every claim on it should be backed by the real build, not just marketing copy. This audits every substantive sentence on that page against the actual codebase, then documents what was implemented to close the real gaps found. The landing page's own text was **not edited** as part of this audit — it's the fixed target, not something to adjust to match whatever the game already did.

## Summary

- **3 real implementation gaps found and closed**: a new campaign starting with 3 real employees + a real starting model ("PotatoLM 0.01"), a real salary-negotiation mechanic in hiring, and a real `data_ops`-headcount bonus to newly trained models' capability (giving "data" in "manage compute, data, and safety debt" an actual mechanical presence, not just a role name).
- **1 claim marked PARCIAL by design**: the pizza-incident flavor text is landing-page copy, not a spec — the underlying experience it describes (autonomous-agent-overspend incidents, investigate/downplay/PR-spin choice patterns) is already 100% real across the incident catalog. Implementing a literal pizza-themed incident would be adding content to match marketing copy rather than closing a real functional gap, and was deliberately not done.
- Every other claim was **already true** before this audit — most from the prior real-estate-progression and visual-target sessions.
