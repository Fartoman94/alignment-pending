# Visual target pass report

Response to `ALIGNMENT_PENDING_ULTIMATE_IMPLEMENTATION_BUNDLE`, whose stated goal was to bring the game "lo más parecido posible" to `01_REFERENCE_TARGET/TARGET_VISUAL_REFERENCE.png`. That reference is a painted, illustrated 2D mockup (hand-drawn-style isometric rooms, painted character portraits, stylized icon art) generated by an image model — not a screenshot of anything built in an engine, and not achievable pixel-for-pixel in this project's actual pipeline (real-time 3D + Godot `Control` UI, procedurally generated geometry/materials, no 2D illustration tool in this environment). The bundle's own `README_VISUAL_TARGET.md` scopes this correctly: "Claude debe **aproximar** la claridad del layout, la vida del garage, la fuerza del branding, la legibilidad de la interfaz, la identidad del management sim" — approximate the layout/clarity/identity, not reproduce the brushwork. That's what this pass did.

## Gameplay checklist: already done

`08_QA_RELEASE/gameplay_target_checklist.md`'s 11 items (new game starts in the garage, hire staff, place/upgrade furniture, train/evaluate/launch models, incidents fire, garage/office/building upgrades, NPCs have real tasks) were **already fully implemented** by the two prior sessions this session continues from (NPC visual rework, real estate/company progression). Re-verified, not re-built. Similarly `08_QA_RELEASE/visual_target_checklist.md`'s items were mostly already closed by the earlier visual-overhaul and NPC-rework passes — garage identifiable/furnished, HUD legible, tabs clear, panels understandable, NPCs visible, training/finance/incident/news panels legible. The one item that genuinely wasn't done: **"Menú principal fuerte."**

## What this pass actually built

### Branding swap
Replaced `game/assets/branding/icon.svg` with the bundle's own icon design (`06_UI_LANDING_BRANDING/alignment_pending_icon.svg`) — a mountain/arrow mark that reads much closer to the reference screenshot's actual title-screen logo than the prior two-triangles-and-a-circle mark. Scaled its 256-viewBox source to the 512-viewBox `tools/render_branding.gd` already assumes (no tool changes needed); rebuilt `icon.ico` from the regenerated PNG set via Pillow. Added a new `wordmark.svg` (icon + "ALIGNMENT PENDING" lockup), recolored light-on-transparent for this project's dark UI (the bundle's source had a white print-background variant).

### Main menu — the actual gap
Full rebuild of `scenes/main_menu.tscn`/`src/menu/main_menu.gd`: the old menu was a centered title + 4 plain buttons on a flat background — the "not fuerte" the checklist flagged. New layout: the icon+wordmark lockup and tagline top-left, 5 stacked buttons (added **Credits**, previously not reachable from the menu at all despite `credits.tscn` already existing and working), a decorative "terminal" panel on the right (a bordered console with a blinking cursor — skipped under `reduced_motion`, same accessibility gate every other purely-decorative animation in this project already respects — and a sticky-note callout), and a motto line. Built with real Godot `StyleBoxFlat`/`Control` nodes, not an attempt at the reference's painted look.

### Intro sequence (new)
`scenes/intro.tscn` + `src/menu/intro_sequence.gd`: 4 short fade-in beats before the main menu (title → tagline → "every great company starts in a garage" → the opening goal), skippable by any key/click/button, and skipped outright under `reduced_motion`. `boot.gd` now routes through it once before the main menu. Content is a plain typed const in the script, not a new `data/*.json` catalog — fixed narrative copy referenced nowhere else, unlike this project's actual tunable content catalogs.

### Resource bar icons
The reference's top HUD strip is icon-led (a $ mark, a people glyph, a chip, a bolt, a diamond) next to each stat. Added a small solid-color dot to each of the 6 resource chips (`Hud._add_chip_icon()`), built programmatically from the chip's own existing semantic color — no new icon image asset (avoids both an asset dependency and Unicode-glyph font-coverage risk), same "procedurally generated, not imported" discipline `ProceduralMeshFactory` already established for 3D geometry.

### Employee card
The reference's staff panel shows a portrait, star-style skill ratings, a loyalty/conscience bar, and a flavor quote — richer than the existing plain-text staff detail block. Added `Hud._build_staff_card()`: a colored avatar (role's `visual_color`, initial letter), the role's top skills as colored `ProgressBar` rows instead of raw numbers, a morale bar, and a one-line flavor quote (a small per-role pool, deterministically picked per staff id — flavor only, no gameplay effect) in a bordered callout, all laid out above the existing full-detail text block (kept, not replaced — it still has fields the card doesn't show: salary, fatigue, traits, hire date, full skill list, status). **Found and fixed a real bug** while verifying this with an actual render (not just `tools/bootstrap.sh`, which never exercises this UI path at all — a real coverage gap, now closed with a dedicated smoke-test block): a ternary array literal (`[x] if cond else []`) doesn't infer as `Array[String]` in this GDScript version, throwing at runtime on every staff detail view. Fixed and now covered by a real assertion, not just "doesn't crash."

### Landing page
Published as a Claude Artifact (not part of the Godot project — a landing page is an external asset, same as the bundle's own wireframe was), built from `06_UI_LANDING_BRANDING/landing_page_wireframe.html`'s structure/copy direction plus the new branding and **real in-engine screenshots captured this session** (the new main menu, a premium office interior, the new employee card, the staff roster) — not stock imagery, not AI-illustrated art. Visual language borrows directly from the actual shipped HUD (the amber/teal/violet/coral semantic chip colors, a scrolling "worldwire" ticker echoing the in-game news feed) rather than generic marketing tropes, so the page reads as *this* game's marketing, not a template.

## Deliberately not done (honest scope boundary)

- **The reference's illustrated 2D art style itself** (painted rooms, painted character portraits, hand-drawn UI chrome): not achievable — this project's rendering pipeline is real-time 3D (imported low-poly `.glb` characters/furniture, procedurally generated materials) plus Godot `Control`-node 2D UI, and this environment has no 2D illustration/image-generation tool to produce painted assets even if the pipeline could ingest them. What's approximated instead is the reference's *information design*: what's on each panel, how it's grouped, what's emphasized — achieved with this project's own real, working visual language (the Art Bible's semantic palette, the pack's actual 3D characters), not a copy of someone else's brushwork.
- **Training data-source selection** (the reference's training panel shows checkboxes for "Wikipedia / Libros licenciados / Internet.zip / Reddit," each tagged with legality/quality/cost): a genuinely new gameplay mechanic, not in any of this bundle's written specs (`03_GAMEPLAY_SYSTEM_SPECS/`, `04_GAME_DATA_JSON/`) — only visible in the mockup image itself. Adding it means new data schema, new `ModelManager` state, new UI, and rebalancing training cost/quality/safety around it — a system-design task on the order of the real-estate pass, not a "make it look like the picture" pass. Worth its own dedicated session.
- **NPC "talk"/"break" states**: the bundle's `03_NPCS_INTELIGENCIA_Y_VIDA.md` asks for NPCs that "conversen, tomen descansos." `StaffAgent`'s state machine (IDLE/MOVING/WORKING) already got idle head-turn/weight-shift and a seated-pose approximation in the prior NPC-rework pass; a literal two-agent "talk" interaction or a dedicated "walk to the coffee corner and stop" break state is a real state-machine expansion with its own interaction/targeting logic, not a visual tweak — deferred for the same reason the training-mechanic above is.
- **Starting-economy numbers**: `04_GAME_DATA_JSON/starting_state.json` proposes very different starting values (cash $18,400 vs. this project's tuned $184,200; 3 pre-hired staff and 6 GPUs already active vs. the deliberate empty-garage start). Not adopted — this project's "empty office, build up from nothing" opening is documented as a deliberate design choice (`docs/design/ART_BIBLE.md`, reaffirmed in the earlier visual-overhaul pass), tuned across many prior balance passes (`docs/design/CORE_LOOP_AND_BALANCE.md`). Copying a concept-art mockup's flavor numbers over already-tuned, tested balance risked real regressions for a purely cosmetic match with no design justification given.
- **"PotatoLM 0.01" current-model-name display**: a nice flavor touch from the mockup's top bar, not added this pass for lack of a clean, low-risk hook into the existing resource strip within this pass's time budget — noted as a good small follow-up, not attempted half-done.
