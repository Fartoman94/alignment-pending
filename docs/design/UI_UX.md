# UI/UX Specification

## Principles
1. The office is primary, spreadsheets are secondary.
2. Every metric change should have a tooltip explaining top causes.
3. High-stakes release choices show projected upside and uncertainty, not hidden gotchas.
4. One consistent right-side Inspector for people/objects/projects.
5. One bottom build/action bar.
6. One top resource strip.

## Main HUD
Top: Cash | Compute | Power | Trust | Safety Debt | Date | Time controls.
Left: objectives/inbox badges.
Bottom: Build, Staff, Research, Models, Deployments, Company, World.
Right: contextual inspector.
Center: 3D world.

## Model release screen
Columns:
- Model card and generation.
- Evaluation results with confidence intervals.
- Expected user/revenue/inference load.
- Known warnings.
- Rollout policy.
Primary actions: Delay / Internal / Beta / Public.

## Incident screen
Clear severity, timeline, what was known before launch, affected systems, response options and expected tradeoffs.

## Accessibility
- UI scale 80–160%.
- Font size presets.
- Full remapping.
- Reduced motion.
- Camera shake toggle.
- High-contrast mode.
- Colorblind-independent icons.
- Pause while reading events.
