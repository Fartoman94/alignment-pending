# Visual audit report

A full visual audit of the current build, requested directly: pull everything pushed so far, find the real graphical defects, fix what's found. This session had not seen the 24 commits pushed between `e693bc4` and `29ebef1` (GIGA_GRAPHICS, the production-kit integration, the generated-humanoid pipeline, the world+NPC overhaul, the garage-recovery pass) — this audit starts from a real `git pull`, not from memory, and every finding below is from an actual render, not a code read.

## Method

Real (non-headless) rendering at every step: a fresh campaign in the garage, a real move to a premium office, the World panel opened through the real `Hud`, the full 136+-model asset gallery, and — critically — real computed `Control.size`/`get_minimum_size()` dumps for the one UI bug, not just screenshots, since a layout bug like that one is invisible to a static `.tscn`/`.gd` read (this exact bug had already been logged in `docs/production/KNOWN_ISSUES.md` as "root cause not identified... would need step-through debugging of actual computed rects").

## Findings

### 1. FIXED — World panel: right-side content overflowed off-screen with no visible panel background

**Severity: high (a core, frequently-opened HUD panel was unreadable).** Already flagged in `KNOWN_ISSUES.md` as "text unreadable at the edge," but the real defect was worse than that description: the entire `RightPanel/Margin` subtree was rendering **646px wide inside a 400px-wide panel**, so text ran directly onto the 3D viewport with no panel background/border visible behind it at all, and several lines were clipped by the screen edge entirely (see `docs/art/screenshots/audit_world_panel_fixed.png` for the corrected version).

**Root cause, found by printing real `get_minimum_size()` on every node in the chain** (not visible from reading the `.tscn`/`.gd` side by side, confirming why the earlier pass couldn't find it that way): a `Label` in `Hud._show_world_panel()` — the "World state — cycles that affect the company, independent of anything you do" header — was missing both `autowrap_mode` and `size_flags_horizontal = SIZE_EXPAND_FILL`. Without those, Godot's `Label.get_minimum_size()` reports its full un-wrapped single-line width (~600px for that sentence) as a hard minimum. A `VBoxContainer`'s own minimum width is the max of its children's minimum widths, so that one label's width propagated all the way up through `DynamicContent` → `Scroll` → `VBox` → `Margin`, and `MarginContainer` (a `Container`) takes `max(anchor-rect size, computed minimum size)` — so `Margin` grew to 646px even though its anchors said 400px. A second, smaller instance of the identical bug was in `_build_real_estate_section()`'s building-listing `info_label` (the long "cap %d — $%d buy / ... — prestige %d, talent %d, regulation %d" line), missing `size_flags_horizontal` (it already had `autowrap_mode`, which wasn't enough on its own).

**Fix**: added `size_flags_horizontal = Control.SIZE_EXPAND_FILL` to both labels (plus `autowrap_mode` on the world-state header, which didn't have it either). Verified by re-printing the same real rects: `Margin` now reports exactly `400×560`, matching `RightPanel`. Also made `RightPanel/Margin`'s anchor block in `hud.tscn` fully explicit (all 4 anchors + all 4 offsets) while investigating — didn't turn out to be the cause, but removes an ambiguous partially-defaulted anchor state either way.

### 2. FIXED — Exterior/city backdrop: `tower.glb` rendered as a massive, flat, incorrectly-lit gray shape dominating the screen

**Severity: high (visible immediately on moving to any higher-tier office — the single most jarring thing on screen).** `Campaign._build_exterior()`'s "dense" richness tier (`premium_office`/`hq_building`) placed `tower.glb` at the same `0.22` scale every other exterior building uses. From the real default gameplay camera, it rendered as an enormous, flat, unlit-looking gray silhouette covering most of the left half of the screen (see the "before" description below — the artifact itself wasn't kept as a committed screenshot, but `audit_exterior_tower_removed.png` is the confirmed-clean "after").

**Confirmed by isolation, not guessed**: removed just that one placement (queue_free() on the exact node, everything else unchanged) and re-rendered — the artifact disappeared completely, nothing else in the scene changed. Checked the model's raw AABB against the other 3 exterior buildings (`small_building_exterior`, `mid_building_exterior`, `hq_building_exterior`) — its size (12 local units tall, vs. 10.5 for `hq_building_exterior`) and pivot (centered, base at Z=0) both look structurally normal, same convention as the others, so this isn't a simple "wrong scale number" fix this pass could safely re-tune blind — something about this specific model's real rendered footprint doesn't match what its AABB alone suggests, and finding out exactly why (a `SubViewport` texture bake `CityBackdrop.build_for_tier()` using the *same* model at scale 1.0 showed a related, though not identical, oversized/dominant result — see finding 3) would need more investigation than this pass had time for.

**Fix**: removed the `tower.glb` placement from `Campaign._build_exterior()`'s dense tier. The remaining 3 buildings (`hq_building_exterior`, `mid_building_exterior`, 2× `small_building_exterior`) already read as a real block/skyline without it — confirmed via the same render used to verify the fix.

### 3. PARTIALLY FIXED — `CityBackdrop`'s office-window skyline texture is illegible at the "dense" tier

**Severity: medium (a small, easy-to-miss decorative texture, not something a player stares at, but currently doesn't show what it's meant to).** The same `tower.glb` model, used by `CityBackdrop._build_street()`'s "dense" tier (the small `SubViewport`-baked texture shown through office windows at `premium_office`/`hq_building`) at its *native* scale (this function has no scale parameter at all, unlike `Campaign._build_exterior()`), completely dominated the 512×256 baked frame — confirmed by rendering the baked texture directly (`SubViewport.get_texture().get_image()`), not by inference. Removed the same placement here too, for the same reason.

**Still not fully legible after that fix** (re-rendered, checked): the baked texture now shows a large, flat, mostly-featureless light panel (likely `hq_building_exterior` or `mid_building_exterior`, still too close to this `SubViewport`'s fixed camera — `Vector3(0, 1.7, 6.0)`, `fov=55`) rather than a recognizable skyline. This is a real, remaining defect, left open rather than papered over with another guess: the two buildings this tier still places need either a smaller scale, a farther Z position, or the backdrop camera itself needs to pull back — any of which is a real, verifiable-by-rendering fix this pass didn't have the remaining time budget to iterate on safely. Tracked in `docs/production/KNOWN_ISSUES.md` below rather than left silently.

## Checked, found acceptable (not bugs)

- **Staff crowding at adjacent garage desks**: an early render (agents mid-pathfinding, captured too soon) looked like two staff members were standing on top of each other at one desk. Re-verified with a real 12-second wall-clock wait (not a `process_frame` count, which this project's `SceneTree`-script test harness doesn't reliably map to real physics time — worth remembering for future audits in this codebase) so pathfinding could actually finish: all 3 staff correctly settle at their own distinct desk, 2 world-units apart. Confirmed the underlying data is correct too (`TaskManager.assign()`/`build_controller.building_position()` return 3 genuinely distinct positions). The desks do read as cozy/tight once staff are seated — a legitimate "small precarious garage" stylistic choice, not a positioning bug.
- **Generated-humanoid vs. flat-mesh character scale/style mismatch**: real, already found and documented by the prior session in `docs/art/HUMANOID_PIPELINE_REPORT.md` ("Known, deliberately deferred gap: scale mismatch") — re-confirmed present in this audit's own garage render (a generated-humanoid character reads visibly bulkier/shorter next to a flat-mesh one at the same desk row), not a new finding, already tracked, already a documented deliberate deferral with reasoning.
- **Asset gallery** (136+ models incl. all character variants): re-rendered in full; no new broken/missing meshes, no other shading anomalies spotted at a full-gallery glance. Label overlap in the grid view is a pre-existing, dev-only-tool legibility issue, not a shipped-game bug.
