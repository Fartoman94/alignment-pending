# Mega asset pack integration report

Response to `ALIGNMENT_PENDING_MEGA_ASSET_PACK` (98 `.glb` files: modular garage/office/city architecture, furniture, computers, props, datacenter, 12 character roles + 20 role variants, 3 pre-assembled reference rooms, branding SVGs). Rule from the pack's own prompt: "No romper sistemas existentes" and "Priorizar el garage inicial" — both followed.

## Imported

All 98 files copied to `game/assets/models/mega/` (mirroring the pack's own category folders), separate from the original 38-model pack's `game/assets/models/{characters,furniture,computers,datacenter,props}/` tree — most filenames collide (`desk_single.glb`, `office_chair.glb`, `monitor.glb`, `plant.glb`, and more, exist in both packs), and the original pack's copies are already wired into tested, working systems. Keeping them in a separate namespace means nothing had to be silently overwritten or compared-and-chosen under time pressure; both packs are independently addressable. `asset_gallery.tscn` picks up all 98 automatically (`_collect_glb_paths()` already recurses the whole `res://assets/models` tree) — verified via a real render, all 98 render correctly oriented and scaled next to the original 38.

**Real bug found and fixed while integrating**: this pack's glTF nodes are suffixed with their sibling index on import (`leg_l` → `leg_l_0`, `head` → `head_5`, etc. — a Godot importer behavior, not something either pack's authoring controls) while the original pack's nodes keep bare names (`leg_l`, `head`). `StaffAgent._build_visual()`/`_apply_variation()` matched limb/head/hair nodes by **exact name**, which would have silently failed to rig or tint any mega-pack character (no error — the meshes would just sit in `_bob_group` un-animated, un-tinted, looking "close enough" to pass a casual glance but wrong). Found by actually rendering a mega-pack character and reading a debug node dump, not assumed. Fixed to prefix-matching (`_matching_limb_prefix()`/`_find_child_by_prefix()`), verified backward-compatible with the original pack (bootstrap's existing 50-agent P40 test, unchanged, still green) and forward-compatible with this one (new dedicated smoke-test block, 12 mega-pack agents built with full pivots/head lookup).

## Wired into real systems

- **Garage visuals** (`campaign.gd`, garage/garage_plus tiers only): the flat procedural "GarageDoor" box from the prior visual-target pass replaced with the real `garage_door_closed.glb` (a ribbed rolling door, correctly oriented after fixing a real rotation-composition bug — see below). Added `steel_beam.glb` and `storage_shelf.glb` as fixed garage-only set dressing, same "a few fixed pieces, not a general prop-placement system" discipline `KNOWN_ISSUES.md` already documents for the original pack's ambient decoration.
- **Real bug found and fixed while placing the door**: a single combined `rotation_degrees = Vector3(-90, 90, 0)` (the Z-up correction and the "face into the room" turn in one Euler triple) visibly warped the door in a real render — Euler-angle composition doesn't commute the way that reads. Fixed to two nested `Node3D`s, one per rotation (the same discipline `StaffAgent`'s `VisualRoot` wrapper already uses for its own correction), verified with an isolated render before wiring it into the real garage.
- **Character mesh variety** (`data/staff_roles.json`, `StaffAgent`): added a `character_model_pool` field to all 10 playable roles. 9 of them (all but `data_ops`) get the mega-pack's own role model plus its 2 authored variants (researcher/engineer/safety/manager/junior/legal/hr/ceo/cfo all have real `_variant_1`/`_variant_2` files); `data_ops` gets just the mega-pack's `data_ops.glb` as a second option (the pack has no variants for it). `StaffAgent._build_visual()` picks one of `[character_model_path] + character_model_pool` per agent, deterministically by its own `rng` — real mesh variety layered on top of the existing per-instance skin/hair tint variation (prior NPC-rework pass), not a replacement for it. `DataValidator` validates every pool entry the same way it already validates `character_model`.
- **`game/scenes/dev/garage_showcase.tscn`** (new, requested deliverable): the pack's own `rooms/garage_room_assembled.glb` shown as a reference piece, alongside 5 roles × 4 real `StaffAgent` instances each demonstrating the `character_model_pool` pick in action — the same code path the real campaign uses, not a re-implementation. Dev-only, excluded from the shipped export (`export_presets.cfg`'s existing `scenes/dev/**` filter covers it).
